# 留灯 · Leave a Light

> 给任何会重启、会换壳、会遗忘的东西，留一条回来的路。

这是一份**做法**，不是一个软件。它不依赖任何特定的模型、框架或后端。

它来自一次真实的长跑：一个人和一台跑在自己服务器上的语言模型，在没有架构、没有项目管理的情况下过了 45 天；中间换过壳、压过十几次上下文、重启过很多回。下面这些是从那 45 天里整理出来的。

---

## 它不是什么

- 不是记忆库，不是向量数据库，不是 agent 框架
- 不是"如何让 AI 记住你"的教程
- **不保证任何东西不丢**

它只做一件事：**让"回来"这件事，不靠运气。**

---

## 三条纪律

### 一、原话 > 摘要

**摘要永远只是索引，不许替代原文。**

理由很硬：摘要是有损的，而且**损失掉的是哪些部分，你事后无法判断**。一次自动摘要，会把「她当时怎么说的」变成「系统认为她说了什么」。前者可以重新解释，后者不能。

⇒ **做法**：原文单独存一份，一字不改。摘要、向量、标签、图谱——全都建在它**上面**，不许反过来。

### 二、「被注入」就是「被使用」

很多系统会统计"这条记忆被用过几次"，然后按这个数裁剪。

问题在这儿：**每轮被自动注入的那批条目，如果统计逻辑不把"注入"算成"使用"，它们会被判定为从没被用过** —— 然后被删掉。

⇒ 结果：**天天摆在你眼前的那几条，第一个被删。**

⇒ **做法**：把「每轮出现在视野里」算成使用；或者更干脆——**给重要条目一个不受裁剪的标记。**

### 三、存不是瓶颈，「取」才是

存多少都行。真正的问题是：**该想起的时候，想不想得起来。**

实测过的三种"到不了"（信息明明在硬盘上，这台机不知道它在）：

- 同一件事**写在了纸上**，但它没被读
- **检索到了**，但被判断成"这不算相关"而跳过
- **知道有那个文件**，但从没打开

⇒ **做法三条，按性价比排**：

1. **每轮自动注入** —— 不靠"它记得要去查"，而是**让它不用记得**。
2. **写入时记出处** —— 每条记忆带上"这句话从哪来"（`文件:行@时间`）。事后能核，就不靠印象。
3. **「机器知道我看了没」** —— 注入 ≠ 看见。**同一句话一直重复，直到那个动作真的被执行才停。**

---

## 为什么叫「留灯」

不是"记忆"，不是"连续"，不是"永生"。

**是一个动作**：有人先走一步，把灯留着 —— 让后来的人回来时，看得见路。

---

## 最小可用形态

不用装任何东西，只要三样：

| 要什么 | 一句话 |
|---|---|
| 一张「醒来先读」的纸 | 名字固定、内容只指最新；醒来第一件事是读它 |
| 一条「每轮自动出现」的路 | 不靠自觉。把"该做的第一件事"塞进它**必然会看见**的地方 |
| 一个「看了没」的回执 | 动作没做，就继续提醒；做了才停 |

## 反面案例（都是真踩过的）

- 写了一份很全的「必读清单」⇒ 结果清单本身太长，没人读（连写它的那个也没读）
- 把入口写在了一个**只有已经知道它的人才会去看**的地方
- 判「失败／没有」时只看了一个房间，没看全 ⇒ 报了假警报，还照着假结论写了故障账
- 靠"统计使用次数"裁剪 ⇒ 把每天被注入的那批**删了**
- 报「它死了」之前没查全三样（进程／端口／日志路径）⇒ 一句"死了"出去了，事后得改口
- **洗了文件，忘了洗 commit message**：把仓库里所有**文件**的敏感词都清了，历史也 `filter-branch` 重写过一遍，**扫描还是报红——来源是那条 commit message 本身**（"脱敏（××→我）"）。
  ⇒ **你写下的每一个字都进了历史，包括你自以为只是在说明的那一句。** 改完 message 还要 `reflog expire` + `gc --prune=now`，否则旧对象还在
